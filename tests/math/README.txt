tests/math: tests of <math.h> (docs/spec/math.md)
=================================================

Run by `make test` (in every model, MODEL=s, c and l) through tests/run-dos;
the cases are in `cases`. Every case's program prints only the rows that
fail, then `ok` (the NAME.expect files say so).

Data
----
data/*.dat are generated by `tests/math/gen` and committed (re-run it only
to change the corpus: the oracle is the host's libm through Perl's POSIX
module, and the last bit of a result and a few of the random arguments
depend on the host, the tests' bounds cover that). A line is

    FUNCTION ARG [ARG2] RESULT ERRNO

with the arguments and the result as 16 hex digits (the bits of a double),
and ERRNO one of 0, EDOM, ERANGE, taken from the spec's tables and never
from the host. `nan` as a result means any NaN. frexp, modf and ldexp have
the extra fields described in the header of `gen`. `gen --verify [N]`
checks the oracle against an independent computation (Math::BigFloat) on
every Nth row: the worst error found, for the functions it covers, is
under 0.7 ulp, so a 4 ulp bound is the implementation's allowance.

Everything about a row that the spec leaves open is left out of the corpus
(see "Left open by the spec" below), so a failure is the implementation's.

Programs (tests/math/*.c, compiled -fpc, linked with tests/support/testio.c)
----------------------------------------------------------------------------
All of them use lib/mathio.h: no floating-point operation is used to
compare. A double is four 16-bit words; the error of an inexact result is
the difference of the integer bit patterns, computed with word arithmetic
(one unit is one ulp); the result must have the expected sign and not be 0,
infinity or NaN unless it is expected to be. A zero, an infinity and a NaN
(unless the row says `nan`) must be bit for bit.

  unary   sin cos tan asin acos atan sinh cosh tanh exp log log10 sqrt
          fabs floor ceil, one file each (sin.dat ...): within 4 ulps, 0
          for sqrt, fabs, floor and ceil; errno cleared before each call
          and exactly the expected one after.
  binary  atan2 pow fmod (atan2.dat, pow.dat, fmod.dat): within 4 ulps, 0
          for fmod; errno as above.
  special frexp modf ldexp: exact, the exponent and the integral part too
          (ldexp's subnormal results are rounded to nearest even).
  errno   every function on the special values and errors (errno.dat, a
          selection of the rows of the other files: every error row and a
          third of the other special rows): errno exactly, and a call that
          expects no error is made again with errno set to 12345, which it
          must leave alone ("never clears errno").
  exact   the exact class, every result bit for bit (exact.dat: f(0)
          identities, integer powers whose results are doubles, pow(x, 0)
          and pow(x, 1), perfect squares, fabs/floor/ceil/fmod; p2n.dat and
          p2p.dat: pow(2, n) for every n from -1074 to 1023, and a few
          pow(-2, n); l10.dat: log10 of the double nearest 10^n for n from
          -307 to 308, which must be exactly n).
  l_fabs, l_sqrt, l_sin, l_pow
          one function each, called once with a known argument: the
          selective linking checks below.

hugeval is the test of HUGE_VAL's object.

Selective linking (for the implementer to finish)
-------------------------------------------------
`members` has only hugeval's line: the names of the helper members are the
implementation's choice, so the set of members a program links cannot be
written before the implementation. What is checked now, by
tests/math/check-link (run by `make test` before the programs, through
rules.mk): l_NAME.MEMBERS contains the member NAME, none of the members of
another public function of <math.h>, and, for fabs (a function on the bits
that links no helper), nothing of libkitchen16's but fabs.

To finish it: when the helper members exist, add lines to `members` (or
members.s, members.c, members.l if the models differ), for example

    l_fabs: fabs c16:cstart
    l_sqrt: sqrt <helpers it needs> c16:cstart
    l_sin:  sin <helpers it needs> c16:cstart
    l_pow:  pow <helpers it needs> c16:cstart

and for the programs with data files, which also link libc16's fopen and
the rest (the c16: members), the same, from `cat build/MODEL/tests/math/
unary.MEMBERS`; check the lists by reading them, that a program links the
function it calls, its helpers and the members it shares, and nothing else.
Note that unary, binary, special, errno and exact each link every function
they test; make a pair of them smaller if one function is not finished.
(The programs that call a function get a link error until it exists;
`make -k MODEL=s test` still builds the others.)

Runtime
-------
Rows per file: 146 to 700, and exact 754, p2n 1074, p2p 1033, l10 616; about
11,000 rows in all, of which about 3,500 are pow calls (the longest are the
sin, cos and tan rows with huge arguments and fmod's with large ratios).
Soft floating point under DOSBox-X's 8086 core is slow: expect a few
minutes for the whole suite in a model (the guess is from the cost of a
transcendental function at about 20,000 to 100,000 cycles, with
tests/run-dos's 600 second limit). Use RUN_DOS_TIMEOUT to raise the limit if
a slow machine needs it, and shorten `cases` locally, one line per file.

Left open by the spec (so not in the corpus; the implementation chooses)
-------------------------------------------------------------------------
- fmod with a NaN argument and a zero y (or an infinite x): the spec gives
  both "NaN, no error" and "domain error".
- pow(0, -inf): "x = 0 and y < 0 is ERANGE" against "pow(x, +-inf) follows
  Annex F without error".
- pow(-inf, y) with y finite and not an integer: domain error (x < 0) or
  Annex F, no error.
- Which NaN is returned when both arguments are NaN (rows say `nan`), and
  a NaN with the sign bit set or a signalling NaN argument (only quiet,
  positive NaNs are used, 7FF8000000000000 and 7FF8000000000123).
- Arguments within a few units of the overflow or underflow thresholds of
  exp, sinh, cosh and pow, where the error class depends on the last bit
  (they are left out so that errno never depends on it).
- atan2, and every function without a range error in the spec's table:
  an underflow to zero or a subnormal gives no error (glibc sets ERANGE
  for atan2(tiny, huge); the spec does not, and the rows say 0).
