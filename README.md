# libkitchen16

The floating point that [libc16](https://github.com/gr-dos/libc16) leaves
out, for 16-bit MS-DOS programs built with Open Watcom C: small, compact
and large memory models, 8086 instructions, no FPU needed. Each function
is its own library member, so a program links only what it calls, and no
Open Watcom runtime code is used (`docs/LICENSE-PROVENANCE.md`). MIT
licensed.

It provides:

- the helpers `wcc -fpc` calls for `double` arithmetic, comparison and
  conversion, with IEEE 754 binary64 semantics (`docs/spec/fpc.md`);
- `vsnprintf`, `snprintf`, `vsprintf`, `sprintf`, `vfprintf`, `fprintf`,
  `vprintf` and `printf`, with `%e %f %g` exactly rounded at any precision
  (`docs/spec/fmt.md`, `fmtio.md`);
- `strtod` and `atof`, correctly rounded (`docs/spec/conv.md`);
- `<math.h>`: C89 7.5 (`docs/spec/math.md`).

libc16 never depends on libkitchen16. libkitchen16 depends on libc16 for
`errno`, `FILE` output and the headers, and a program that uses it links
libc16's startup. `docs/ABI.md` is the contract with the programs that link
it; `docs/DESIGN.md` explains the choices.

## Using a release

Each release has `libkitchen16-VERSION.zip` and
`libkitchen16-VERSION.zip.sha256`. Check the archive before unpacking it:

    sha256sum -c libkitchen16-0.01.zip.sha256
    unzip libkitchen16-0.01.zip

It holds one directory:

| Path | What |
|---|---|
| `libkitchen16-0.01/VERSION` | the version |
| `lib/LIBK16.LIB`, `lib/LIBK16C.LIB`, `lib/LIBK16L.LIB` | the library for the small, compact and large memory models |
| `include/` | `math.h` and `kitchen16.h` |
| `docs/` | the ABI, design, provenance and per-module specs, and the similarity audit (`AUDIT.txt`) |
| `BUILD.txt` | the source revision, the pinned toolchain, the flags and how to rebuild |
| `tools/fetch-watcom` | downloads and checks the pinned Open Watcom snapshot (not included) |
| `LICENSE`, `README.md` | |

Compile as a libc16 consumer does, with `-fpc`, and both include
directories (libkitchen16's first); link libkitchen16's library, then
libc16's, with no default libraries:

    wcc -zl -zld -x -ms -0 -s -fpc -bt=dos -Ilibkitchen16-0.01/include \
        -Ilibc16-0.07/include hello.c
    wlink option nodefaultlibs format dos file hello.obj \
        library libkitchen16-0.01/lib/LIBK16.LIB \
        library libc16-0.07/lib/LIBC16.LIB

For the compact model compile with `-mc` and link `LIBK16C.LIB` and
`LIBC16C.LIB`; for the large model, `-ml`, `LIBK16L.LIB` and `LIBC16L.LIB`.
Include libc16's headers before `<kitchen16.h>`. `docs/ABI.md`, "Consumer
build", explains each flag.

### In a program

A program fetches a pinned release with `scripts/fetch-libkitchen16`
(`docs/CONSUMERS.md`, "Using libkitchen16"): a copy of
`consumers/fetch-libkitchen16` with the version and SHA-256 of a release. It
downloads the exact versioned ZIP, checks it before unpacking it, and
unpacks it to `build/libkitchen16`. To build against a local checkout (built
with `make`), point `LIBKITCHEN16_ROOT` at it; its `build/stage` has the
release layout.

## Building from source

On Linux, with Perl 5.40 or later as `perl`, a C compiler and make (to build
JWasm), git, curl, unzip and xz, and `dosbox-x` for the tests:

    make            # build/s/LIBK16.LIB, build/c/LIBK16C.LIB and
                    # build/l/LIBK16L.LIB, staged with the headers in build/stage
    make test       # the ABI, link-map, 8086 and selective-linking checks,
                    # and the test programs under DOSBox-X, in every model
    make audit      # the similarity audit of each library
    make MODEL=c test   # lib, test or audit for one model (s, c or l)
    make dist       # build/dist/libkitchen16-VERSION.zip and its .sha256, and make src
    make src        # build/dist/libkitchen16-VERSION-src.tar.gz and its .sha256
    make install PREFIX=DIR   # copy build/stage to DIR

The pinned Open Watcom snapshot and JWasm are fetched into `build/tools`,
and the pinned libc16 release into `build/libc16` (`scripts/fetch-libc16`).
To build against another libc16, for example a checkout built with `make`:

    make LIBC16_ROOT=../libc16

The tests compare against the host's C library as an oracle. The
corpora are generated by `tests/SUITE/gen` and committed.

## Releasing

`VERSION` holds the version, DOS style (0.01, 0.02, ... 1.00), not semantic
versioning. When a pull request that changes it is merged to `main`, the
release workflow (`.github/workflows/release.yml`) tags the merge commit
`v<VERSION>`. It then builds, tests and audits, packages and checks the ZIP
and the source archive, and publishes a GitHub release with both and their
checksums. A push to `main` whose `VERSION` already has a tag publishes no
release. Running the workflow by hand on `main` does the same check, which
bootstraps or retries a release whose tag does not exist yet.

`main` is protected as libc16's is: a change reaches it by a pull request
whose `ci` check passes, and force pushes and deletion are refused.

### Source archive

Each release also has `libkitchen16-VERSION-src.tar.gz` and its `.sha256`:
the complete source, for programs that link libkitchen16 into a program whose
license requires its corresponding source, such as the GPL. `scripts/make-src`
makes it with `git archive` from the tagged commit, never from a working
tree, under the single directory `libkitchen16-VERSION/`. It is the same for
the same commit, and `git get-tar-commit-id` reads the commit from it. To
build it, unpack it and run `make` as above; BUILD.txt then shows the
revision as `unknown`. `scripts/check-src` checks an archive against its
commit, and `make src` (and so `make dist`, in CI) makes and checks one.
